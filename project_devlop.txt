  SECTION 1: EXCEL DATA FETCHING & TABLE DISPLAY
================================================================================

1.1  HOW IS EXCEL DATA FETCHED?
--------------------------------------------------------------------------------

  Method:        File upload (drag-and-drop or file browser click)
  Library:       ExcelJS 4.3.0 (server-side parsing)
  Processing:    Server-side (Express.js backend)
  File Types:    .xlsx and .xls (validated via regex: /\.xlsx?$/i)

  DATA FLOW FROM FILE SELECTION TO TABLE DISPLAY:

  Step 1 — User drops/selects an Excel file
           Location: frontend/components/FileUpload.tsx (lines 17-28)
           Action:   Validates file extension, converts to base64

  Step 2 — Sheet Detection
           API Call:  POST /api/get-sheets { fileData: base64 }
           Backend:   backend/src/services/excelService.js (lines 21-26)
           Library:   ExcelJS Workbook().xlsx.load(buffer)
           Returns:   Array of sheet names [{index, name}, ...]

  Step 3 — Sheet Selection (if multiple sheets)
           Location:  frontend/components/SheetSelector.tsx
           Action:    User selects which sheet to process

  Step 4 — Format Detection
           API Call:  POST /api/detect-format { fileData, sheetIndex }
           AI Used:   OpenAI gpt-4o-mini (temperature 0.1)
           Returns:   { format: A|B|C, confidence, suggestedMapping, rowCount }

  Step 5 — Manual Mapping (if confidence < 80%)
           Location:  frontend/components/ManualMappingDialog.tsx
           Action:    User manually maps Excel columns to fields

  Step 6 — Data Normalization
           API Call:  POST /api/normalize { fileData, sheetIndex, format, mapping }
           Backend:   backend/src/controllers/normalizeController.js
           Returns:   { rows: NormalizedRow[], originalData, rawRows }

  Step 7 — Table Display
           Location:  frontend/components/DataTable.tsx
           Library:   react-window (FixedSizeList) for virtual scrolling


1.2  HOW IS DATA SHOWN IN THE TABLE?
--------------------------------------------------------------------------------

  Table Component:    Custom DataTable using react-window (FixedSizeList)
  Location:           frontend/components/DataTable.tsx (183 lines)
  Virtual Scrolling:  YES — react-window 1.8.10
  Pagination:         NO — uses virtual scrolling instead
  Sorting:            NO
  Filtering:          NO
  Row Height:         36px (constant)
  Table Height:       600px max (dynamic: Math.min(600, rows * 36))
  Inline Editing:     YES — click any editable cell
                      Enter to save, Escape to cancel, blur to auto-save


1.3  KEY CODE SNIPPETS
--------------------------------------------------------------------------------

  EXCEL UPLOAD HANDLER:
  File: frontend/components/FileUpload.tsx (lines 17-28)
  - Validates extension: /\.xlsx?$/i
  - Converts to base64 via lib/utils.ts:fileToBase64() (lines 32-42)
  - Calls onFileSelected callback

  PARSER CONFIGURATION:
  File: backend/src/services/excelService.js (lines 3-17)

  DATA TRANSFORMATION:
  File: backend/src/controllers/normalizeController.js
  - Format A: Direct column mapping (lines 12-28)
  - Format B: OpenAI gpt-4o-mini parses single-column data (lines 79-89)
  - Format C: Hybrid — direct + AI for missing manufacturer (lines 31-65)
  - Deduplication applied to all formats (deduplicationService.js)

  TABLE RENDERING:
  File: frontend/components/DataTable.tsx (lines 160-180)
  - FixedSizeList from react-window
  - itemSize={36}, height={Math.min(600, rows.length * 36)}

  SECTION 3: AI ROLE IN THE PROJECT
================================================================================

3.1  AI FEATURES IMPLEMENTED
--------------------------------------------------------------------------------

  [x] Format Detection — Detects Excel structure (Format A/B/C)
  [x] Data Normalization — Parses unstructured single-column data
  [x] Manufacturer Website Verification — Searches web for product pages
  [x] Part Number Identification — Verifies item numbers against web sources
  [x] Data Enrichment — Adds verified source, score, website URL, source type
  [x] Rule Enforcement — Applies data quality rules on low-confidence results
  [x] Supplementary Classification — Classifies as internal_instruction vs part_specification
  [x] Manufacturer Inference — Infers manufacturer when empty
  [x] Swedish Translation — Translates Swedish terms to English
  [x] Deduplication — Removes duplicate itemNumber/typeDesignation

3.2  HOW AI PROCESSES EXCEL DATA
--------------------------------------------------------------------------------

  DATA SENT TO AI:
  - description, manufacturer, itemNumber, typeDesignation
  - supplementary (only on retry when score < 70 and type = part_specification)
  - NEVER sends: internalItemNumber (Rule R1)

  WHAT AI RETURNS:
  - Verified/corrected: description, manufacturer, item_number, type_designation
  - New fields: verified_source, verification_score (0-100), website_id, source_type
  - Metadata: manufacturer_website, manufacturer_inferred
  - Supplementary: supplementary_used, supplementary_changed, supplementary_original

  FALLBACK CHAIN:
  1. Gemini 2.5-Flash (primary) — web search verification
  2. If score < 70 AND supplementary is part_specification:
     → Re-verify WITH supplementary using Gemini
  3. If score still < 70:
     → Claude Sonnet 4.6 for rule enforcement
  4. Cache result for future lookups

  RATE LIMITING / BATCHING:
  - Concurrency: 5 simultaneous verifications (p-limit)
  - Batch size: 5 rows per progress update
  - Max rows: 10,000 hard limit
  - Request timeout: 30 seconds per AI call
  - Retry: 3 attempts with exponential backoff (1s, 2s, 4s)
  - Cache: SHA256(manufacturer|itemNumber|typeDesignation), TTL 24 hours

3.3  AI PERFORMANCE METRICS
--------------------------------------------------------------------------------

  Average Response Time:   ~2-5 seconds per row (Gemini with web search)
  Claude Fallback Time:    ~1-3 seconds per row (no web search)
  OpenAI Normalization:    ~0.5-1 second per row

  Success Rate:            Dependent on data quality; cache improves repeat runs
  Cost per 1000 rows:      Varies by provider pricing
                           - Gemini: ~$0.10-0.30 per 1000 rows (flash pricing)
                           - Claude fallback: only triggered for score < 70
                           - OpenAI: only for format detection + Format B/C rows

  Cache Hit Rate:          Tracked via cacheService.getStats()
                           Reported in SSE 'complete' event

3.4  AI CODE IMPLEMENTATION
--------------------------------------------------------------------------------

  PROVIDER 1: OpenAI (gpt-4o-mini) — Format Detection & Normalization
  File: backend/src/services/openaiService.js
  - Model: gpt-4o-mini
  - Temperature: 0.1 (deterministic)
  - Response format: JSON mode
  - Used for: detectFormat(), normalizeRow()

  PROVIDER 2: Google Gemini (gemini-2.5-flash) — Web Verification (PRIMARY)
  File: backend/src/services/geminiService.js
  - Model: gemini-2.5-flash
  - Tools: [{ googleSearch: {} }] — built-in Google Search
  - Search sequence: manufacturer website → Octopart → Mouser → RS Online → PLCHardware
  - Post-processing: URL validation via HEAD request (5s timeout)
  - URL status: valid | redirected | broken | timeout
  - Broken/timeout → clears websiteId and sourceType

  PROVIDER 3: Anthropic Claude (claude-sonnet-4-6) — Rule Enforcement Fallback
  File: backend/src/services/claudeService.js
  - Model: claude-sonnet-4-6-20250514
  - Triggered: When Gemini score < 70
  - Rules enforced:
    1. Deduplicate itemNumber == typeDesignation
    2. Infer manufacturer if empty (50% confidence threshold)
    3. Remove ERS. prefixes
    4. Translate Swedish
    5. Don't modify supplementary unless incorrect part data
    6. Don't invent URLs

  URL VALIDATION:
  File: backend/src/services/urlValidatorService.js
  - Validates every website_id returned by Gemini
  - Method: HEAD request with 5-second timeout
  - If broken/timeout: clears URL, downgrades source type

  MOCK MODE:
  File: backend/src/services/mocks/
  - MOCK_MODE=true in .env → returns sample data without real API calls
  - Per-provider toggles: OPENAI_MOCK_MODE, GEMINI_MOCK_MODE, CLAUDE_MOCK_MODE
